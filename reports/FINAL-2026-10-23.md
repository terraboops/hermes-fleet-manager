## 1. Executive summary

Backends tested:

- mlx: baseline. Measured.
- remote: loopback `laya serve --backend mlx` (parity) and `laya serve --backend cpu` (latency). Measured. No real network hop.
- cpu: F16 (`quant_level=none`), Q8_0 (default `auto`/`8bit`), Q4_K_M (latency only, no parity run). Measured.
- cuda, rocm, legacy-gpu, vulkan: probed, UNAVAILABLE on this Mac (no NVIDIA, no ROCm, no Vulkan runtime on macOS). Not measured. They ship enabled after a passing probe and are flagged unverified.
- rule-only (no model): measured for latency and behaviour.

Thresholds changed: none. The gate keeps one global threshold, `score >= 0.59` (`LAYA_GATE_CHOICE_THRESHOLD`). No per-backend threshold was added and no config or gate code changed. Why:

- The approved drift bound sets the recalibration cap at 0. A backend that needs another threshold fails the bound.
- The gate has no per-backend threshold mechanism.
- Best-fit thresholds from the harness are weak (F16 0.5882 with 2 flips left, Q8_0 0.5991 with 5 flips left) and would lose the 10:1 swallowed-escalation asymmetry the gate was tuned for.

Drift bound: approved on 2026-10-23 as written (at most 3 decision flips in 307 rows, no recalibration; commit 1d7335c). A backend outside the bound ships flagged and is never the automatic choice. The earlier reports were written while the bound was still PROPOSED. The measured numbers are unchanged by the approval. Only the status changed.

Conflict check against cron 708aaba1d802, run 2026-10-14 09:15 (`~/.hermes/cron/output/708aaba1d802/2026-10-14_09-16-06.md`, file still present): no conflict.

- That report covers lane-1 rule volume after the retune (56 to 81 escalations; top rule "still stopped 11 min after it went quiet", 37 of 81).
- It contains no lane-3 or Laya score threshold and no per-backend value.
- The only lane-3 threshold in the repo is 0.59, set in CHANGELOG before that retune. It is unchanged.
- Gap: the retuned lane-1 values live in the running gate, not in a file that could be diffed.

Overall: 8 of 10 checklist items PASS cleanly. Item 2 (forced CPU within the bound) FAILS on measurement and ships flagged. Item 9 (thos zero-config) PASSES on a warm cache and FAILS on a cold cache (no model host).

## 5. Open issues and follow-ups

For the FAIL items:

- Item 2, CPU drift. Options for the owner: accept F16 as a flagged near-miss (one flip over), or build per-backend thresholds and approve recalibration (the bound forbids that today), or keep CPU as a flagged rung only. Current behaviour already matches the approved rule: outside-bound backends are flagged and never the automatic choice. Follow-up: add `--max-pass-to-hold`, `--min-spearman` and `--reference` to `laya parity`; measure Q4_K_M parity.
- Item 9, cold cache. No model host exists (memo Q8), so `manifest.model.url` is null. Fresh install works only with a cached model, an imported bundle, or `THOS_LAYA_MODEL_URL`. Set a host and re-release the manifest.

Other gaps found, none a FAIL:

- Gate SIGTERM orphans the `llama-server` child (no shutdown hook in `laya_gate.py` main). Needs a handler that closes the manager, plus a test. Not fixed because `laya_gate.py` carried uncommitted edits from other work.
- `/health` fallback events carry no timestamp.
- Rejected `LAYA_QUANT_LEVEL` and `LAYA_MAX_SEQ_LEN` values appear only in the gate log, not in `/health`.
- Transient `ok` / `model_loaded` mismatch on `serve /healthz` during start.
- A typo in `LAYA_BACKEND` silently falls to auto (documented contract). A stricter design would refuse to start.
- `doctor --dry-run` ignores `LAYA_BACKEND`.
- GPU rungs (cuda, rocm, legacy-gpu, vulkan) never ran on hardware. CUDA and ROCm asset hashes are GitHub release digests, not independently hashed.
- Linux and Windows paths in the thos plugin are unit-tested only.
- thos idle policy undecided (default `--sleep-idle-seconds 1800`; child outlives bb).
- thos remote rung client not in this release; MLX adoption is opt-in via `THOS_LAYA_MLX_URL`.
- Remote latency is loopback only. Latency numbers need an idle-host re-run.
- thos `m1a` check 3 fails: `spikes/bb-plugin-thos-control` is missing from that repo (older than this work).
- Memo Q6 and Q7 (real-event regression set, GPU hardware) remain open.
- No separate document exists for the 2026-10-13 gate retune.
