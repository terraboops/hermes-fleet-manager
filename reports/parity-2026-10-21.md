## Why no threshold

1. No agreed bound exists. The only bound is `DRIFT_BOUND.md`, marked PROPOSED, owner approval NOT GRANTED, approver and date empty. Nothing in config or other docs sets one. Flagged, not guessed. The proposed numbers are shown only as reference.
2. The proposed bound forbids this fix: "Recalibration cap: 0. A backend that needs a different threshold fails." Its best-fit threshold is "a diagnostic only". A per-backend threshold is the recalibration it excludes.
3. The gate has no per-backend threshold mechanism. `laya_gate.py` has one global `ESCALATE_IF_AT_LEAST` (env `LAYA_GATE_CHOICE_THRESHOLD`, 0.59), and `config.example.yaml` has no laya threshold keys. Adding one is a gate code change, and `laya_gate.py` has uncommitted changes in the working tree from other work.
4. The harness best-fit values are real but weak: F16 0.5882 (2 flips remain, 0.9935), Q8_0 0.5991 (5 flips remain, 0.9837; 0.0091 from 0.59, past the 0.005 review line). A backend with a shifted threshold would also lose the 10:1 swallowed-escalation asymmetry the gate was tuned for. Not applied.

Decision for the owner: approve or amend the bound; then either accept F16 CPU as a documented near-miss (one flip over, 0.0004 under on the near band) or approve recalibration for CPU backends, which needs the per-backend mechanism built first.
